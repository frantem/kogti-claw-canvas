## Корректный возврат HTTP 404 для несуществующих страниц

### Проблема
Яндекс.Вебмастер сообщает, что сайт `kogtistudio.by` некорректно отдаёт код 404. Проверка подтверждает: запрос несуществующей страницы (`/this-page-does-not-exist-12345`) возвращает `HTTP/2 200` вместо `404 Not Found` — сервер отдаёт `index.html` вообще для любого пути. Это мешает индексации.

Сайт хостится на собственном VPS под управлением nginx (см. `deploy/nginx.example.conf`). В репозитории уже подготовлены правильные конфиги с белым списком маршрутов и страницей `public/404.html`, но на работающем сервере, судя по ответу, действует упрощённая SPA-конфигурация (`try_files $uri /index.html`), которая отдаёт 200 на всё.

### Что нужно сделать

#### 1. Обновить `deploy/nginx.example.conf`
- Добавить в белый список валидный маршрут `/privacy` (он есть в `App.tsx` и в `public/routes.json`, но отсутствует в текущем nginx-конфиге).
- Убедиться, что `location @react_routes` корректно возвращает 404 для всех остальных путей через `error_page 404 /404.html;`.
- Добавить явный `return 404;` с заголовком `Cache-Control: no-store` для несуществующих маршрутов, чтобы Яндекс не кешировал.

#### 2. Обновить `deploy/README.md`
Добавить чёткий раздел «Как обновить конфиг для корректного 404», с командами:
```
sudo cp deploy/nginx.example.conf /etc/nginx/sites-available/kogti
sudo nginx -t && sudo systemctl reload nginx
curl -I https://kogtistudio.by/non-existent-page-test
# ожидаемый ответ: HTTP/2 404
```

#### 3. Улучшить SPA-страницу `src/pages/NotFound.tsx`
Несмотря на то, что HTTP-код контролируется только сервером, добавить на клиенте:
- `<meta name="robots" content="noindex">` через `useEffect` (динамически), чтобы сигнализировать поисковикам не индексировать страницу, даже если код 200 проскочит.
- `document.title = "404 — Страница не найдена | KOGTI"`.

Это страховка для случаев, когда запрос идёт через Lovable preview/published хостинг, где код 200 управляется платформой.

### Технические детали

Текущий рабочий конфиг на сервере, вероятно, содержит просто:
```
location / { try_files $uri $uri/ /index.html; }
```
Заменить на конструкцию из `nginx.example.conf` с `@react_routes` и явным белым списком `/`, `/auth`, `/admin`, `/privacy`. Тогда `/random-path` уйдёт в `return 404` → отрендерится `public/404.html` со статусом 404.

### Важно
Изменения в коде проекта (nginx-конфиг и README) не повлияют на работающий сервер автоматически — владельцу сайта нужно вручную подключиться по SSH, скопировать обновлённый конфиг и перезагрузить nginx (команды будут в README).
